03

내 역할

TERRAFORMEKS 클러스터 코드화

terraform-aws-modules/eks로 t3.medium 노드 그룹(3대, 1~4대)과 IRSA를 구성하고, Access Entry로 팀원 권한을 부여했다. ArgoCD도 Terraform Helm Release로 함께 설치했다.

CI변경된 서비스만 빌드하는 Matrix

paths-filter로 바뀐 서비스만 골라 Matrix를 만들고, 백엔드는 Postgres · Redis 서비스 컨테이너를 띄워 Gradle 테스트, 프론트엔드는 npm 빌드를 실행했다.

SECURITYTrivy 스캔으로 Push 차단

이미지를 로컬에 먼저 빌드하고 HIGH · CRITICAL 취약점이 있으면 실패시켜, 검사를 통과한 이미지만 ECR에 올라가도록 했다.

GITOPSSHA Tag → values 갱신 → 자동 Sync

CI가 이미지 Tag를 Helm values에 커밋하면 ArgoCD가 감지해 배포한다. App of Apps(root-dev / root-prod)와 prune · selfHeal로 클러스터를 Git 상태에 맞췄다.

PROD GUARDprod 배포 전 매니페스트 검증

prod 파이프라인은 helm lint와 렌더링 후 namespace: dev, targetRevision: joon, 빈 값이 섞여 있으면 실패하도록 해 dev 설정 유입을 막았다.

HELM공통 기본값 + 서비스별 Override

단일 hotel Chart에서 serviceDefaults를 서비스별 값과 병합했다. HPA(2~5, CPU 70%), 무중단 Rolling Update(maxUnavailable: 0), ALB Ingress 경로 라우팅을 공통으로 적용했다.

04

트러블슈팅

ALB 환경에서 로그인 후 401 반복

증상EKS에 배포한 뒤 로그인 API는 성공하지만, 이후 인증이 필요한 요청에서 401이 반복됐다.
원인JWT 쿠키에 Secure 속성이 붙어 있었는데 ALB가 HTTP로만 열려 있어, 브라우저가 쿠키를 저장하지 않았다.
해결Secure 적용 여부를 환경 변수(COOKIE_SECURE)로 분리하고, 환경별 Helm values에서 값을 주입하도록 변경.
결과ALB를 통한 로그인 후 쿠키가 정상 저장되고, 마이페이지 · 예약 API가 401 없이 동작

초기화 전 Liveness Probe로 Pod 반복 재시작

증상배포 직후 Spring Boot Pod가 준비되기 전에 재시작을 반복했다.
원인애플리케이션 초기화가 끝나기 전에 Liveness Probe가 실패로 판정했다.
해결Chart 공통값에서 initialDelaySeconds를 45초, failureThreshold를 6으로 올려 초기화 시간을 확보.
결과시작 중 불필요한 재시작이 줄고, 배포 후 Pod가 안정적으로 Ready 상태에 도달

클러스터에서 API 호출 실패 (CORS · 경로)

증상로컬에서는 동작하던 프론트엔드 API 호출이 EKS 환경에서는 실패했다.
원인서비스마다 CORS 설정이 흩어져 있었고, 프론트엔드가 로컬 서비스 주소를 직접 호출하고 있었다.
해결CORS 설정을 공통화하고 API 호출을 상대경로로 바꾼 뒤, ALB Ingress에서 /api/v1/* 경로별로 서비스에 라우팅.
결과대기열(/api/v1/queue)을 포함한 API가 Ingress를 통해 정상 전달되어, 로컬과 클러스터 양쪽에서 동작
