01

프로젝트 개요

실습용 VM을 만들고 지우는 대신, 실제로 매일 쓰는 서비스를 계속 운영하면서 배포 · 네트워크 · 데이터 문제를 직접 겪어 보기 위한 환경입니다.

Raspberry Pi Linux 서버에서 Wiki.js 기술 위키와 개인 웹 도구를 운영합니다. 위키는 Docker Compose로 Wiki.js와 PostgreSQL을 분리해 띄우고, 웹 도구는 Nginx가 정적 파일로 서비스합니다. 외부 접근은 Cloudflare Tunnel로만 받아 집 공유기의 포트를 열지 않았고, 웹 도구는 GitHub Actions에서 빌드해 Pi에 설치한 Self-hosted Runner가 배포합니다.

GOAL실사용 서비스를 직접 운영

설치하고 끝나는 실습이 아니라, 바뀌고 고장 나는 서비스를 계속 유지합니다.

EDGEOrigin을 공개하지 않는 노출

Cloudflare Tunnel이 바깥으로 연결을 맺어, 인바운드 포트 없이 서브도메인별로 서비스를 연결합니다.

DELIVERY빌드와 배포 Runner 분리

무거운 빌드는 GitHub-hosted Runner에서, 파일 반영만 Pi의 Self-hosted Runner에서 실행합니다.

DATA컨테이너와 데이터 분리

위키 데이터는 PostgreSQL 볼륨과 SQL Dump로 관리해 컨테이너를 다시 만들어도 유지됩니다.

03

구현 내용

CI/CDGitHub Actions 2단계 파이프라인

Build Job이 lint와 build를 통과한 결과물만 Artifact로 올리고, Deploy Job이 이를 받아 반영합니다. lint가 실패하면 배포까지 가지 않습니다.

RUNNERSelf-hosted Runner 라벨 라우팅

Pi에 Runner를 설치하고 raspberrypi · deploy · 서비스 이름 라벨을 붙여, 배포 Job이 정해진 장비에서만 실행되게 했습니다.

RELEASE동기화 방식의 정적 배포

rsync --delete로 서비스 디렉터리를 빌드 결과와 똑같이 맞춰 이전 파일이 남지 않게 하고, 배포 후 디렉터리 755 · 파일 644로 권한을 정리합니다.

CONCURRENCY중복 배포 방지

워크플로에 concurrency 그룹을 두어, 연속으로 push해도 마지막 변경만 배포되도록 이전 실행을 취소합니다.

CONTAINERDocker Compose 위키 구성

Wiki.js와 PostgreSQL을 컨테이너로 분리하고 볼륨으로 데이터를 유지하며, SQL Dump로 백업합니다.

HARDWAREmicroSD → NVMe 이전

계속 쓰고 지우는 서버 특성상 수명과 속도가 약한 microSD를 NVMe로 바꿔 저장장치를 안정화했습니다.
